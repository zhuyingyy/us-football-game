# us橄榄球玩法 · Field Goal Rush

在线试玩：https://zhuyingyy.github.io/us-football-game/

GitHub Pages 从 `main` 分支的 `docs/` 发布。更新游戏后运行 `pnpm build`，将 `dist/` 内容复制到 `docs/`（保留 `.nojekyll`），提交并推送即可更新线上版本。

一个 780 × 1644 的竖屏 2D / 2.5D 射门小游戏。Vite + TypeScript + Phaser 3，无后端、无物理引擎。

## 运行

macOS 可直接双击本目录的 **启动游戏.command**。脚本优先使用本机 Node，也兼容这台机器上的 Codex 自带运行环境。关闭终端或按 Ctrl+C 停止服务。

有 Node.js 22.18+ 的开发环境也可运行：

```sh
pnpm install
pnpm dev
```

按终端中的地址打开。手机与电脑处于同一局域网时，可打开终端中的 Network 地址。生产包：`pnpm build`；本地检查生产包：`pnpm preview`。

## 如何试玩

常驻 UI 仅保留音符样式的声音开关、绿色星星金币、GOALS 命中数、三颗 3D 生命心形，以及独立的 `00:30` 倒计时。顶部为无描边半透明面板；页面带有 iPhone 风格的顶部状态栏与底部 Home 指示条（装饰预览，时间固定为 9:41，不读取设备状态）。没有标题、距离、风力文字、连击栏或底部说明；点击顶部信息区不会射门。音符按钮统一控制背景配乐和合成音效。

配乐为原创 128 BPM 美式橄榄球球场风格：铜管号角短句、行进小军鼓、重拍大鼓、看台踏步 / 拍手节奏和低音。采用号角呼应、鼓组过渡、铜管回归的 30 秒循环编排；乐器均为合成音色，不是现场录音。首次有效射门或手动打开声音后播放；暂停、静音和切走窗口停止播放，恢复后从原位置继续。结算与重玩沿用同一条音轨，不叠加；销毁场景时清理音轨。音量为 28%，让进球反馈保持清晰。

每进一球就换球门位置、起脚点和挑战类型。观察这一球的瞄准线与球门，等落点进入门内时点击。有风时，琥珀色小点表示预计落点，应该让这个点对准球门。点击瞬间锁定射门方向、球门位置和风力，飞行期间停止移动，并使用同一份快照进行判定。

蓝色轨迹跟随球飞行，球的中心通过两根立柱内缘之间即命中；25 码的中心 ±36px 内为 PERFECT，随距离和球门一同缩小。当前版仅判定水平中心位置，不做球体碰撞或真实物理。

点击反馈约 60ms，飞行 560ms，落点判定后 120ms 开始下一球，再用 220ms 平滑移动 / 缩放球门。整次射门到再次可操作约 1 秒；650ms 的得分反馈叠在场景下方，和转场并行播放。转场结束前禁止踢球；暂停会同时冻结转场、射门线和球门运动。普通命中 GOOD，球门外 NO GOOD。顶部左侧音符按钮开关合成音效。电脑也支持空格踢球、Esc 暂停；切走窗口会暂停。

- 每局 30 秒，从第一脚有效射门开始计时。时间耗尽或生命归零即结束；暂停和切走窗口冻结倒计时。最后 5 秒倒计时变为红色。
- 压哨前已踢出的球会完成判定并计分；计时归零后不能再出脚。飞行、反馈、转场均消耗时间。
- PERFECT +3 金币、GOOD +1、NO GOOD 0。每连续 3 次 PERFECT 额外 +3（不参与双倍）；GOOD 或失误会打断奖励周期。金币是本局分数，当前没有跨局钱包或商店。
- 只统计连续 PERFECT；GOOD 或 NO GOOD 中断当前连击。连击奖励只在命中反馈中短暂显示，不占用常驻 UI。
- 开局 3 条命，仅 NO GOOD 扣 1 条命。第三次失误或时间耗尽后停止下一球，结算仅显示本局金币、命中数和重玩按钮。最高纪录仍在本地保存，不在当前精简 UI 展示。
- 结算弹窗出现时播放一次音效：三条生命耗尽播放约 1 秒下行失败提示；30 秒结束且仍有生命播放约 1.3 秒上行欢庆提示。压哨球先完成判定再播放；生命同时归零时优先失败提示。静音、切走窗口和重开会停止尚未播完的提示。
- 点击 PLAY AGAIN（或空格）重开，金币 / 连击 / 生命 / 距离 / 倒计时重置，最高纪录保留。挑战轮换模式使用独立存储键，不混用之前不同奖励规则的纪录。最高分只存在当前浏览器本地，不联网；浏览器禁止存储时本次会话仍可正常玩。
- 每进 1 球升级，25 → 30 → 35 → 40 → 45 → 50 → 55 → 60 码；失误保持当前难度。命中判定、球门大小、飞行终点同步缩放。距离在 60 码封顶，关卡与挑战继续递增，移动会继续加速、球门和 PERFECT 区域缓慢缩小。后续加速趋于上限，避免无限加速变成不可能的关卡。
- 所有题型的球门换位后都会持续匀速左右往返，到边界立即折返。ANGLE：偏侧小幅移动；TRACK：移动范围更大、速度更快。两种常规题交替，每第三题为 GOLD：移动中的球门再缩小 20%，基础金币翻倍（GOOD +2、PERFECT +6）。速度随命中数逐步增加；点击射门时仍锁定本次球门位置与判定。
- 命中后从左 / 中 / 右三条区域中选择不同位置，保证新位置与上一脚锁定球门相差至少 105px；起脚位置也不连续重复。失误保留同一题、风力和起脚点。每题初始瞄准点在门外，不能在转场后连续盲点得分。
- GOLD 挑战用金色导轨与球体环境光区分，保持双倍基础金币；移动球门与挑战轮换机制保留。命中时短暂显示 GOOD / PERFECT 与得分，奖励反馈可与下一球并行。
- 进 5 球后加入固定风偏，风力上限 1.8。琥珀色点显示含风偏的预计落点。题目生成会让瞄准范围覆盖目标，并限制球门活动范围不出屏。

## 主要文件

- `src/main.ts`：Phaser 启动、FIT 等比适配、开发热更新清理。
- `src/config/GameTuning.ts`：全部手感参数和资源路径。
- `src/config/levels.ts`：8 档距离、三类挑战、无连续重复的球门 / 起脚位置、双倍奖励、风力和后段难度，以及分数 / 生命 / 升级 / 转场规则。
- `src/game/RunState.ts`：金币、每 3 次 Perfect 奖励、生命、结算统计和最高纪录存储。
- `src/game/RunClock.ts`：基于单调时钟的倒计时，不依赖帧率和动画速度，支持暂停与恢复。
- `src/scenes/GameScene.ts`：唯一场景、双移动、风偏提示、TRANSITION / AIMING / KICKING / RESULT / GAME_OVER、点击快照判定、HUD、暂停与重开。
- `src/game/BallController.ts`：呼吸轮廓光、接地阴影、起脚压缩、弧线飞行、缩放、自旋、固定时间间隔尾迹采样。
- `src/game/Effects.ts`：冲击波、限量粒子、结果文字、合成音效。
- `src/game/math.ts`：无 Phaser 依赖的轨迹、判定函数。
- `tests/game.test.ts`：判定、计分 / 连击、第三次失误、难度封顶、双移动可达性、命中窗口、风偏落点、存储异常等测试。
- `tests/browser-smoke.mjs`：真实浏览器触摸输入、连点、暂停、重启、重复循环和适配检查。
- `tests/music-smoke.mjs`：真实浏览器音频解锁、PCM 输出、静音 / 暂停恢复、循环、重玩与场景清理检查。
- `tests/end-sound-smoke.mjs`：失败 / 欢庆音效的实际 PCM 输出，以及静音、取消未来音符、重开时的清理。
- `tests/goal-lighting-smoke.mjs`：对比普通 / GOLD 瞄准光下的实际球门像素，防止居中偏绿，并检查环境反光跟随位置与缩放。
- `scripts/render-music.py`：原创配乐的音符、编曲与离线合成源文件（NumPy；运行游戏不需要 Python）。

## 调手感

修改 `src/config/GameTuning.ts` 后开发服务器会自动更新：

- `flightDuration: 560`：飞行毫秒数；越小越快。
- `arcHeight: 296`：弧线抬升幅度；越大越高。
- `ballEndScale: 0.28`：球到达球门时的尺寸比例。
- `ballSpin: Math.PI * 5`：整段飞行转动角度。
- `perfectRange: 36`：中心 PERFECT 的半宽；越大越宽容，需小于球门半宽。
- `goalWidth: 240`：球门立柱内缘之间的宽度，画面和判定一起调整。
- `trailLength: 16`、`trailSampleInterval: 20`、`trailAlpha: 0.85`：尾迹采样数、采样时间间隔（ms）与亮度。
- `resultDuration: 650`：反馈停留毫秒数。

距离和基础尺寸编辑 `src/config/levels.ts` 的 `LEVELS`。`createRound()` 控制 ANGLE / TRACK / GOLD 调度、球门与起脚位置、运动范围、奖励倍数和 60 码之后的平滑难度递增。分数、生命、每关进球数、`windFactor: 16` 和 `transitionDuration: 220` 编辑 `RUN_RULES`。本轮没有开发调参面板。

## 替换素材

所有运行时素材均在 `public/assets/`，不依赖外部图片或字体服务：

- 背景：覆盖 `stadium.webp`，使用 780 × 1644 或同宽高比图片，地平线建议在约 y=950。图片里不要包含球、球门、UI。
- 橄榄球：覆盖 `football-forward.png`（400 × 600 RGBA），保持轻微前倾透视、透明背景，画布留白尽量接近当前版本。`ballHeight` 控制显示大小。旧版 `football.webp` 和 `football-lit.png` 保留备选，可在 `ASSETS.football` 切换。
- 球门：覆盖 `goal-rendered.png`，当前为带金属反光、圆管体积和蓝色护垫纹理的单张透明图，600 × 1044 像素、300 × 522 逻辑尺寸。立柱内缘约为逻辑 x=30 / 270；保持开口与底座锚点可直接替换。`goal-combined.png` 保留为旧版。地面接触阴影与柔化的球门投影由代码绘制，随位置与缩放同步。
- 配乐：`stadium-rush.m4a`，30 秒 AAC 音轨；如果替换为不同长度，同步修改 `GameScene.create()` 的音乐 marker 时长。

背景来自最新 Figma，球使用独立生成素材。红色球采用轻微前倾透视、凸起缝线和青紫轮廓光，不带底座与闪电。青色发射导轨沿恒定曲率的圆弧摆动，居中时变为直线，首尾渐隐，箭头随曲线转向，微粒沿曲线前进；导轨显示在球门框前方。呼吸光和草地泛光为代码效果，暂停时一起冻结。球门与护垫以单张透明 PNG 展示；尾迹和彩纸由代码绘制。音效使用 Web Audio 合成，配乐使用本地音频文件。原始图与配乐 WAV 保留在 `outputs/source-assets/`；制作记录见 `ASSET_NOTES.md`。

## 验证

`pnpm test` 运行逻辑测试；`pnpm build` 包含严格 TypeScript 检查。

浏览器检查需要本机 Chrome、正在运行的开发服务器以及 Playwright。可从已有安装提供模块路径：

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node tests/browser-smoke.mjs
```

也可自行安装 Playwright 后直接运行脚本。脚本通过仅开发环境暴露的游戏实例固定瞄准时刻，实际使用浏览器触摸 / 鼠标输入。生产环境不会暴露这个实例。

逻辑测试覆盖金币奖励、连击中断、计时启动 / 暂停 / 归零、生命、存储容错，以及前 40 关、7 种随机种子下每种挑战和风偏的可达性、位置不重复、换位距离与起脚点。浏览器测试覆盖真实触摸、连点锁、压哨球、瞄准 / 转场中超时、暂停和切走窗口、结算重开、10 次连续射门、最高纪录保留、对象和监听器数量及四种尺寸适配。尚未在实体 iOS / Android 设备上验证性能。

## 阶段边界

当前实现 30 秒限时、3 条生命、金币计分、连击奖励、结算、最高纪录和距离递进；采用斜射 / 移动球门 / 黄金精准球 + 进球随机换位 + 风偏 + 平滑转场。仍然只有一个 Gameplay Scene，没有引入商店、装备升级、皮肤或联网排行榜。

适配和生命周期实现参考 [Phaser Scale Manager](https://docs.phaser.io/phaser/concepts/scale-manager)、[Phaser Scenes](https://docs.phaser.io/phaser/concepts/scenes)；开发服务器采用 [Vite](https://vite.dev/guide/)。
